# AutomationHub

## Project Status

Current stage: Phase 5 (Global Hotkeys) complete. Workflows can be assigned a global hotkey (recorded in the editor), the app runs in the system tray (close hides instead of quitting, Quit is in the tray menu), and hotkeys run workflows from anywhere via globalShortcut. Progress events broadcast to all windows. Conflict/invalid shortcuts are reported on save.

Git repository is initialized and pushed to GitHub (mansprj/AutomationHub). Changes are committed and pushed after each task.

## Goal

AutomationHub is a Windows desktop application that allows users to automate repetitive desktop actions through a clean graphical interface.

The application should eventually support:

- Launch applications
- Close applications
- Restart applications
- Execute command sequences
- Global hotkeys
- Macros
- User profiles
- Startup automation
- Plugin system
- Custom workflows

The project should prioritize maintainability and scalability over fast feature implementation.

Project structure

- src/main — Electron main process (window, tray, IPC, process management, hotkey manager)
- src/preload — contextBridge API exposed to the renderer
- src/renderer — React UI (Vite)
- src/shared — types shared between main and renderer
- resources — app assets (tray icon)

## First Functional Goal

Implement a working desktop application capable of restarting Discord.

Expected flow:

User presses button

↓

Electron receives request

↓

Discord process terminates

↓

Discord launches again

↓

UI displays success message

This feature validates the complete application architecture.

## Long-Term Vision

AutomationHub should evolve into a desktop automation platform rather than a collection of scripts.

Every feature should be modular.

Every system should be replaceable.

Architecture must remain clean from the beginning.
