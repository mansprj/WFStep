Supported actions

---

## Phase 4

Workflow Engine

Users can combine actions into sequences.

Implementation

- [x] Shared Workflow type + runtime validator (src/shared/workflows.ts)
- [x] Workflow persistence (workflows.json in userData) + CRUD
- [x] Sequential workflow runner with progress events and cancellation (src/main/workflowRunner.ts)
- [x] workflows:* IPC channels + workflow:progress events
- [x] Renderer Workflows panel (list, step editor, run/cancel progress)
- [x] Action form helpers shared by ActionRunner and WorkflowEditor (src/renderer/src/actionForm.ts)

Notes

- Runner stops on the first failed step; cancellation via workflows:cancel.
- Applications library (src/shared/apps.ts, src/main/appsManager.ts) was added before Phase 4: saved apps persist on disk and restart/stop uses the executable image name.

Goal

Automation becomes visual.

---

## Phase 5

Global Hotkeys

Features

- [x] Assign a hotkey to any workflow (recorded in the editor, persisted on disk)
- [x] Run workflows from anywhere via globalShortcut
- [x] Validation of shortcuts (conflicts with the system/other workflows are reported on save)
- [x] Tray integration: app keeps running in the background, close = hide to tray, Quit from tray menu

Implementation

- [x] `hotkey` field on the shared Workflow type + validator (src/shared/workflows.ts)
- [x] Hotkey manager in main using globalShortcut (src/main/hotkeyManager.ts), re-registered on workflow add/update/remove
- [x] workflowRunner now broadcasts progress to all windows instead of the invoking sender (hotkey runs work without a renderer event)
- [x] Tray icon (resources/tray.png) + close-to-tray behaviour (src/main/index.ts)
- [x] Renderer: hotkey recorder field (Ctrl/Alt required) + hotkey badge in the workflow list

Notes

- Enable/disable a hotkey by assigning or clearing it on the workflow (no separate global toggle yet).
- A hotkey only works while the app runs in the tray; quitting is done via the tray menu.

Goal

Automation without opening the application.
